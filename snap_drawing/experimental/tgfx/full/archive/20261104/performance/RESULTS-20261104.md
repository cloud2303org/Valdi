# Skia / full TGFX mobile Release comparison

Date: November 4, 2026. Lottie remains enabled.

The current replacement saves Android size but does not provide a general performance win. Android is slower in every measured native GPU scene and every managed bitmap scene. iOS Metal has lower observed medians for vector/text/bitmap, higher medians for SVG/Lottie, and large across-run variability. Phone power and presented FPS were not measured.

## Method and acceptance

- Same dirty experimental source revision `02a8f990819c11ce8df25bcc0344c042368dcc20`; backend selector is the controlled switch.
- Actual optimized production exports: `-c opt --snap_flavor=production --strip=always`; Hermes, inline assets, identical minimal exported modules, Lottie/codecs retained.
- Android ARM64 API 36 emulator on Apple M4, GLES through Android Emulator OpenGL ES Translator. iOS ARM64 iOS 26.5 Simulator, Metal. No physical device was used.
- Each family/platform/backend: three fresh process runs, order Skia 1 / TGFX 1 / TGFX 2 / Skia 2 / Skia 3 / TGFX 3. Eight foreground seconds before startup, 30 warmups and 300 measured frames per scene at 360x640.
- No concurrent compiler/build and no per-frame screenshots or PNG encoding during measured loops. Saved replay gates passed 4/4 for all 24 formal runs with no warnings. Recorded walkthrough probes are excluded.
- All 24 complete reports passed required canaries; 32,400 measured frames. Dynamic Lottie first/last contents must differ. Means/P95s are recomputed from the complete 300-value arrays.
- Tables report the median of three run means and the median of three within-run nearest-rank P95 values, not a pooled confidence estimate. Ranges are all three run means. No statistical significance is claimed.
- Native: actual Skia Ganesh and TGFX GPU surfaces, including synchronous RGBA readback every frame. This measures completed GPU rendering plus readback throughput, not display presentation.
- Managed: actual Hermes and drawing wrapper API. Skia uses CPU bitmap raster, while TGFX uploads/renders/readbacks. These are real API costs, not GPU-versus-GPU comparisons.
- Imported vendor configurations were retained and recorded. Outer optimization is identical, but dependency recipes differ: Android TGFX effective `-Os`, ThorVG optimization 3/SIMD/no LTO. This measures the current integrated replacement, not equally tuned renderer internals.

## CPU activity and power

| Workload scope | Skia process CPU ms | TGFX process CPU ms | Ratio |
|---|---:|---:|---:|
| android / native | 897.2 | 2832.7 | 3.16x |
| ios / native | 655.8 | 663.7 | 1.01x |
| android / managed | 835.0 | 8168.0 | 9.78x |
| ios / managed | 667.8 | 935.6 | 1.40x |

Native CPU scope is the sum of measured scene loops only (1,500 frames/run). Managed scope is the whole process between started/finished callbacks and includes setup/warmup/verification/report overhead (1,200 measured frames/run plus warmups). Compare backends within each row; do not compare the families as equal work. Driver/host GPU processes are outside these CPU totals.

These are activity proxies, not watts, joules, energy per frame, battery drain or thermal behavior. Native iOS CPU medians are nearly equal, with wide run ranges. No power-saving claim is supported. A cabled comparable phone workload with energy rails or external power instrumentation remains necessary.

Android APKs differ only in `lib/arm64-v8a/libvaldi_runtime.so` and `assets/provenance.json`; DEX, TS modules, assets and resources are byte-identical. Both use the identical stripped `libc++_shared.so` (1,253,544 bytes); original unstripped companion inputs and APKs were preserved. Release is non-debuggable, locally test-signed, minification disabled equally. This is a minimal benchmark app, not a predicted percentage for the user business app or Play delivery.

iOS totals are simulator-only file-byte sums, excluding external symbol sidecars. They are not allocated filesystem blocks, an IPA, a device slice, encrypted App Store delivery or a thinned download. The normalized copies were not deployed. Lottie remains in both backends.

## Interpretation and next gates

- Current Android replacement trades about 0.86 MiB of runtime code savings for clear regressions in these completed rendering/readback workloads. It is not ready to claim a performance benefit or become the default solely on these results.
- TGFX SVG/Lottie includes the production ThorVG CPU raster plus TGFX image upload/composition. Results describe the complete replacement pipeline, not TGFX alone.
- Investigate Android vector replay and managed bitmap transfer costs before broader rollout. Profile the same scene without readback at a real presentation surface as a separate gate.
- Presented frame rate/jank, sustained physical-device behavior, energy and iOS device/App Store size are still unmeasured. Simulator results do not fill those gates.
